## Public rendering and hosting

`npm run build` uses existing Vite and React server-rendering APIs **at build time**, without a production server or new packages. It renders only the five static public components, without loading accounts, credentials, drafts, private APIs or database content. The normal client app takes over using its existing React root and session checks; this is not a hydration or authentication rewrite.

Vercel rewrites serve each generated public page and retain separate SPA shells. Account/private/unknown routes receive a noindex shell; sensitive routes also receive X-Robots-Tag configuration. Course search has static metadata, and course detail routes have an indexable generic shell so crawlers can render their API-backed content rather than inherit the private noindex shell. Valid course details set their own canonical and metadata after loading; missing/error course results retain noindex in the client.

**Remaining rendering limitation:** catalog results, individual course content and individualized School Locator views still depend on client APIs. Do not prerender the stale seed catalog or advertise unpublished courses. Before considering SSR for course content, evaluate a build snapshot of the authoritative *published* public catalog with a freshness/rebuild policy, removal handling and reliable API access. No live backend access was available to verify such a snapshot during this review.

The local QA server reproduced the intended static routing, response types and CSP. Actual Vercel routing, cache behavior and production metrics must be verified after a separately reviewed deployment.

## DNS and Resend - inspection only

Public DNS answers observed:

- `learnmatch.online TXT`: no records; no root SPF.
- `_dmarc.learnmatch.online TXT`: `v=DMARC1; p=none;`.
- `resend._domainkey.learnmatch.online TXT`: RSA public key is present.
- `send.learnmatch.online CNAME`: `send.forge.rmta.net`.
- Resolved sending SPF: `v=spf1 ip4:52.3.252.119 ip4:44.222.39.36 ip4:199.249.231.0/24 ~all`.
- Resolved sending MX: priority 10, `feedback.forge.rmta.net`.
- Root CAA: no records returned.

The CNAME-managed records are consistent with [Resend Forge](https://resend.com/blog/announcing-resend-forge), which manages sending infrastructure through a CNAME. Resend documents that its [return-path subdomain](https://resend.com/changelog/custom-return-path) defaults to `send` and participates in SPF authentication and DMARC alignment. Do not overwrite this CNAME with legacy SES SPF/MX records or add conflicting records at the same name.

The existing key returned HTTP 401 `restricted_api_key` for GET `/domains`, confirming it cannot inspect provider domain status. DNS publication does not prove provider verification, actual message signing, inbox delivery or DMARC alignment. Those require provider-console access and headers from an already received legitimate message. No email was sent and no key permission was expanded. Root SPF, DMARC enforcement and CAA changes remain review items, without speculative replacement records.
